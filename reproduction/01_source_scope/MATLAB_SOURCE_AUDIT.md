## 2. 论文声称的方法

论文的主问题是带有限运输资源和 AGV 充电约束的动态柔性作业车间调度（DFJSP-T），目标为最小化最大完工时间和总能耗。

论文的主算法是 QNSGA-II：NSGA-II 全局搜索，加问题导向混合初始化，再用 Q-learning 自适应选择六个邻域算子做局部搜索。

论文的三种算法对比对象是 NSGA-II、MOEA/D、MOPSO。消融实验为：

- A：随机初始化的经典 NSGA-II；
- B：使用混合初始化、无局部搜索的 NSGA-II；
- C：使用混合初始化和随机邻域搜索、但无 Q-learning；
- 完整 QNSGA-II：混合初始化和 Q-learning 邻域搜索。

论文的三类动态事件是订单撤销、机器故障和 AGV 故障；各自比较继续执行初始方案（IS）、论文重调度策略（RS）和完全重调度（CS/CRS）。

## 3. 代码中确认的静态算法工作流

### 3.1 完整 QNSGA-II 的真实入口

完整 Q-learning 版本位于 `initial_NSGA-II/initial_INSGA_II.m`，而不是名称为 `QNSGA-II` 的目录。其活动流程为：

1. 建立染色体并调用混合初始化 `init`。
2. 对每个个体调用 `fitness`；`fitness` 再调用 `sorting` 完成调度解码。
3. 二元锦标赛选择 `tournament_selection`。
4. `variation` 进行交叉与变异并评价子代。
5. 父代和子代合并，经 `non_domination` 排序和拥挤度处理，保留前 `pop` 个个体。
6. 若策略字符串包含 `VNS`，按两个目标的中位数把种群分成 4 个状态。
7. 使用 4×6 Q 表和动态 epsilon-greedy 选择 N1–N6。
8. `VNS` 生成邻域解，依据支配关系和归一化目标改进量计算奖励。
9. 按 `Q(s,a) <- Q(s,a) + alpha * (reward + gamma*max(Q(s',:)) - Q(s,a))` 更新 Q 表。
10. 原种群与可接受邻域解再次合并、非支配排序并截断。
11. 迭代结束后保留 rank=1 的非重复目标解，并重新解码输出机器表、AGV 表和能耗记录。

### 3.2 六个局部搜索动作

- N1：选择相邻位置区间并逆序插入/翻转 OS。
- N2：删除两个 OS 位置，再按删除次序重新插入。
- N3：随机改变一个工序的可选机器。
- N4：依据机器负载，把重载机器上的可选工序转移到较轻机器。
- N5：随机改变某工序使用的 AGV。
- N6：利用提前到达且空载 AGV 的等待区间，尝试替代另一运输任务。

### 3.3 编码、变异与解码

主要静态实验代码设置 `dim = 5 * sum(operaVec)`，实际染色体为 OS、MS、AS、空载速度、负载速度五段。`variation` 对 OS 使用保持工件工序数量合法的交叉/交换，对设备和速度段执行多点交换或重置。

`fitness -> sorting` 是核心解码链。`sorting` 按 OS 顺序读取 MS、AS 和两段速度，维护机器/AGV时间表、AGV位置与电量；电量不足时插入前往充电和充电任务；空载、负载运输及机器加工均采用可用时间段插入逻辑。输出包括 makespan、机器能耗、AGV能耗、电量轨迹和充电次数。

### 3.4 混合初始化

当前静态主版本实际采用 40%/30%/30%：

- 第一子群：Tent 混沌映射生成 OS/MS/AS/速度段；
- 第二子群：面向较短累计加工时间和较近 AGV 的启发式初始化；
- 第三子群：面向较低机器能耗和较低 AGV 累计负载的启发式初始化。

代码中还存在 60%/20%/20% 版本以及生成 OS 的不同方式，不能在 Python 中任意混用。

## 4. 对比算法和消融版本的代码归属

- 完整 QNSGA-II：`initial_NSGA-II/initial_INSGA_II.m`，策略包含 VNS 时执行 Q-learning。
- C（随机邻域）：目录 `QNSGA-II/initial_INSGA_II.m`。虽然初始化了 Q 表，但动作始终 `randperm`，没有 Q 更新；它不是完整 QNSGA-II。
- B（混合初始化）：`Multi-NSGA-II/initial_INSGA_II.m`。使用混合 `init`，但 `vns_chrom=[]`，不做局部搜索。
- A（经典 NSGA-II）：`NSGA-II/NSGA2.m`，入口先用普通 `init` 产生初始种群。
- `VNSNSGA-II` 版本引用未在函数内建立的 `ST`、`s`、`Qtable`，不能作为已确认可运行实现。
- MOEA/D：权重向量、邻域、切比雪夫分解更新；代码参数包含 `delta=0.8`、邻域规模约 `pop/20`，并存在为对齐评价次数而随机跳过部分评价的逻辑。
- MOPSO：惯性权重 0.4、`C1=C2=2`、外部档案和网格选择；代码还加入随机三邻域局部搜索，因此它不是未经修改的纯 MOPSO。

## 5. 动态重调度代码结构

动态代码分为集成目录、订单撤销专用目录、AGV故障专用目录和备份目录。同类函数并非全部相同，不能按文件名覆盖。

- 订单撤销：先根据事件时刻分割已完成、进行中和未开始工序，删除被撤销订单；RS 保持规定的 OS/MS 部分，重新选择允许变化的编码；CRS 重新初始化剩余问题；IS 继续原方案或做最少修补。
- 机器故障：记录故障机器、发生和修复时间；非故障机器上的工序尽量固定，故障机器后续工序按策略重新选机，AGV分配可调整。
- AGV故障：区分故障发生时的负载/空载状态，维护修复后的继续运输状态；机器选择通常固定，OS/AS按策略允许调整。
- 动态评价除 makespan、能耗外，还计算机器改变率、AGV能耗平衡/标准差、加工开始时间偏差等不稳定性分量。

## 6. 论文与源码、源码版本之间的关键差异

以下差异足以影响 baseline，必须在第 2 步形成明确规格和裁决记录：

1. 论文写三段 OS/MS/AS；静态主实验实现是五段并显式优化空载/负载速度。集成动态版本又出现三段实现。
2. 论文混合初始化为 60%/20%/20%；当前静态主实现为 40%/30%/30%，仓库中两种实现均存在。
3. 论文 epsilon 为 `1/(1+exp(1.1-5g/GEN))`；静态主实现使用 `1/(1+exp(-(8(g+1)/GEN-3)))`，部分动态版本又使用接近论文的另一式。
4. 部分 `fitness.m` 的第二目标是 `EG_M_SUM + EG_A_SUM`，另一些活动版本却是 `EG_M_SUM`，虽然仍计算并输出 AGV 能耗。
5. 论文公平性要求比较算法与 QNSGA-II 使用相同 CPU 时间；部分静态入口以迭代数停止，另一组 NSGA-II/MOEA-D/MOPSO以时间停止。
6. 静态“算法对比”入口中 NSGA-II、MOEA/D、MOPSO调用被注释，活动代码只运行主算法；完整批量比较不能直接由当前入口一键重现。
7. MOPSO实现额外使用VNS，MOEA/D含随机削减评价次数的特殊处理；比较算法的定义必须按论文实验代码原样固化，而不能替换成库默认实现。
8. 论文说每算法每实例独立运行20次；当前若干入口只含单次或短迭代调试配置，批量协议散落于注释块和结果脚本。
9. 源码未统一设置随机种子，MATLAB与Python不能追求逐随机轨迹一致，只能先做固定染色体/固定随机流的组件一致性，再做统计复现。
10. 同名函数通过当前目录和 `addpath` 解析；若一次把所有目录加入路径，会调用错误版本。

## 7. 可运行性审计

- MATLAB `checkcode` 能解析静态算法、静态消融、参数设置、集成动态和订单撤销等主要入口，但报告了旧式 Excel API、动态数组增长等非致命问题。
- AGV故障专用 `dif_main.m` 在第49行附近存在 MATLAB 语法解析错误，当前文件不能直接作为无修改的可执行真值入口。
- 若干动态入口存在命名不一致、候选变量或停止条件版本漂移；因此“文件齐全”不等于“整套实验可直接运行”。
- 本阶段没有修改原 MATLAB 源码，也没有用猜测修复这些问题。

## 8. 第 2 步前的基线边界

- 1902个路径均保留；去重只用于阅读，不删除副本。
- 以实际活动代码为代码证据，以论文为论文证据；二者冲突必须记账，不能静默统一。

- 不先“优化”MATLAB中的疑似错误；先建立原行为测试，再决定兼容模式和论文规格模式。
- 完整 QNSGA-II、三种对比算法、A/B/C 消融、三种动态事件和 IS/RS/CS 都属于 baseline 范围。
- 上述未解释差异未裁决前，不宣称完整 baseline 成立。

## 9. 第 1 步结论

主算法、对比算法、消融关系、公共底层模块和动态策略代码均已定位到真实行为层面。源码不是一套单一、完全一致且可直接执行的发布包，而是包含实验版本、备份、副本、注释实验和若干缺陷的工作目录。因此第 2 步必须先形成“论文规格—代码实现—选择理由”三列式规范，再进行 Python 实现；直接逐文件机械翻译会得到一个来源混杂、不能证明有效的 baseline。
