# 数据层规格与差异

## 1. 数据层边界

本步只负责把原始实验输入转换成稳定、可校验的 Python 对象，不实现染色体、初始化、解码、目标函数或优化算法。

统一输入由三部分组成：FJSP 实例、机器距离和能耗资源、AGV 参数。机器、工件和工序编号在对照表示中保持 MATLAB 的 1 起始语义；后续若算法内部使用 0 起始下标，必须在模块边界显式转换。

## 2. 与 MATLAB 一致的转换规则

- `.fjs` 首行读取工件数和机器数，第三个统计字段不参与原算法。
- 每个后续非空行对应一个工件，依次读取工序数及各工序的候选机器—加工时间对。
- 原 `benchmarkRead.m` 先构造带 `Inf` 的 `jobInfo`，再用 `find` 得到 `candidateMachine`。因此候选机器最终按机器编号升序排列，而不是保持 `.fjs` 的书写顺序。Python 已复现这个细节。
- 机器距离不能直接读取工作簿中的残留矩阵。原 `dif_main.m` 会先调用 `distance_from_xy(machineNum)`，按“机器仓库坐标”以曼哈顿距离覆盖工作表。转换器同样从坐标重新计算完整 15 台机器的距离，再按当前实例机器数截取。
- AGV 数量采用第3步锁定的映射：10/15/20 个工件分别使用 3/4/5 辆；其余 AGV 参数保持源码数值。

## 3. Gate 1 比较内容

Mk01—Mk10 均由原 MATLAB `benchmarkRead.m` 生成独立 JSON 参照。测试逐项比较工件数、机器数、各工件工序数、每道工序候选机器及其加工时间。任何一个机器映射或加工时间不同都会失败。

## 4. 已发现且未静默修正的源码矛盾

静态入口的最低电量检查表达式是：

`distance_MAX / AGVSpeed(end) * (AGVEnergy.free(end) + AGVEnergy.load(end))`

按 Mk05 的真实距离与源码参数计算为 168，而源码设置 `AGVEG_MIN = 16.8`，会触发原入口的报错条件。这很可能涉及单位换算遗漏，但没有证据允许自动除以 10。

Python 同时保留 16.8 和原表达式计算结果，不擅自改值，也不把物理单位矛盾误判为输入格式错误。该事项必须在实现能耗目标和正式运行前裁决。当前 Gate 1 的“通过”只表示输入解析与 MATLAB 一致。

