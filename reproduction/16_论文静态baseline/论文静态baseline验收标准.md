# 论文静态 baseline 验收标准

## 1. 目标与名称

本阶段目标是建立 `paper-static-baseline-v1.0`：以论文定义的静态机器–AGV协同调度问题为统一口径，继承现有 `Python-NEW` 中已经验证的实现，并能作为后续版本A中 A0–A3 的固定、公平比较基础。

该名称只有在本文全部验收门通过后才能使用。验收前统一称为“论文静态 baseline 候选”。

## 2. 适用范围

纳入范围：

- 静态输入、资源参数和 Brandimarte Mk01–Mk10；
- 染色体、初始化、静态解码、Makespan和TEC；
- QNSGA-II、NSGA-II、MOEA/D、MOPSO；
- A、B、C、full四个原论文消融版本；
- N1–N6、Q-learning和共享多目标算子；
- HV、IGD、C-metric、Spacing；
- 静态重复实验、结果记录、统计汇总和审计。

排除范围：订单撤销、机器故障、AGV故障、IS/RS/CS、RSI及其他动态重调度内容。

## 3. 验收总原则

1. 论文定义用于确定拟复现的静态问题、目标和正式实验协议。
2. MATLAB实际调用路径用于补充论文省略的实现细节，但不得静默覆盖论文定义。
3. 论文与MATLAB冲突时必须登记、分析影响并形成明确裁决；保留原 `matlab_observed` 行为，不回写或美化旧结果。
4. 现有Python组件只有在来源、行为和适用范围均未改变时才能继承其验证证据。
5. 不以“测试通过”代替统计复现，也不以“实验完成”代替论文主张获得支持。

## 4. 验收门

### S0｜身份、来源与静态边界

通过条件：

- 候选分支从提交 `dca5adda2bfb9ca9252caabaff05f31b637772b8` 建立；
- 记录分支、提交、Python版本、依赖、硬件和源文件SHA-256；
- 原MATLAB、现有 `main`、标签 `baseline-matlab-observed-v1.0` 及旧结果保持不变；
- 静态运行入口不依赖动态模块；
- 所有新增或变更文件按 `verbatim_copy`、`mechanical_split`、`new_metadata`、`behavior_change` 分类。

失败条件：来源不明、修改冻结baseline、静态入口仍依赖动态路径，或存在未登记的行为变化。

### S1｜静态输入一致性

通过条件：

- Mk01–Mk10及机器、AGV、速度、能耗和运输参数可追溯到论文、MATLAB输入或冻结资源文件；
- Python与选定MATLAB静态入口加载的实例规模、工序数、机器资格、加工时间和资源参数 materially identical；
- 输入与转换文件具有可复核SHA-256；
- 不使用测试数据反向选择参数。

### S2｜染色体与初始化口径

通过条件：

- 对“三段还是五段”形成书面裁决，说明论文证据、MATLAB证据、选择及影响；
- OS、MS、AS及可能存在的速度段定义完整且索引一致；
- 初始化比例对“60/20/20还是40/30/30”形成同等级裁决；
- 初始化、交叉、变异和N1–N6始终生成合法染色体；
-固定输入或固定随机流下，Python与选定MATLAB口径一致。

### S3｜统一静态解码与目标

通过条件：

- Makespan是否包含成品返回卸载站得到唯一、可引用的论文静态定义；
- TEC包含的机器加工、机器空闲、AGV运输及充电能耗项逐项列明；
- QNSGA-II、NSGA-II、MOEA/D、MOPSO及A/B/C/full使用同一个正式解码与目标口径；
- 固定染色体下，机器分配、AGV分配、开始/完成时间、空载/载货移动、充电、Makespan和TEC与选定MATLAB参考在规定容差内一致；
- 目标差异不能通过仅改字段名称或汇总脚本掩盖。

任何算法仍优化不同物理量时，本门不通过。

### S4｜算法与多目标算子

通过条件：

- 四个优化器保持独立入口，不用库默认实现替代论文或MATLAB特定逻辑；
- 种群选择、交叉、变异、非支配排序、拥挤度、精英保留和停止条件可追溯；
- MOEA/D的权重、邻域、标量化及评价规则得到确认；
- MOPSO的粒子更新、档案、网格和附加VNS得到确认；
- 固定目标矩阵或固定种群下，Python与参考结果一致；
- 四算法除其方法本身外，共享S1–S3确认的数据、解码和目标。

### S5｜Q-learning与消融归因

通过条件：

- 对论文epsilon与MATLAB静态epsilon形成书面裁决；
- 四状态、N1–N6动作、奖励、探索/利用、Q更新和接受规则可逐步复述并由测试覆盖；
- Q表在full中实际更新，在C中不更新且动作随机；
- A、B、C、full只改变各自声明的组件，其他数据、目标、预算和公共参数一致；
- 相同随机控制下关闭新增组件能够恢复对应对照行为。

### S6｜论文静态实验协议

通过条件：

- 在正式结果生成前冻结实例、算法、参数、种群、停止规则、重复数、种子政策、预算、超时和失败处理；
- Mk01–Mk10、每实例每算法20次及论文规定参数得到来源确认；
- QNSGA-II与三个比较算法的公平预算规则明确，记录实际墙钟时间和真实解码次数；
- A/B/C/full使用相同的公平预算；
- 训练、开发、验证和最终测试边界明确；
- 每次运行保存配置、种子、提交、输入哈希、原始Pareto解、目标、曲线、评价次数、耗时、失败和环境信息；
- HV、IGD、C-metric和Spacing的归一化、参考集及参考点固定且公开。

### S7｜统计复现与最终冻结

通过条件：

- 正式网格完整执行，失败、超时和不利结果不被删除；
- 报告每实例、每独立运行的原始结果、描述统计、效果大小和不确定性；
- 所有被比较算法具有同一目标身份，不进行跨口径排名；
- 论文主要静态算法排序和消融方向得到复现；或者每一个足以改变论文中心结论的差异都获得可复核、非事后猜测的证据解释；
- 不存在未解释的模型、解码、目标、约束、预算或实验协议差异；
- 结果、表格、结论与原始文件可通过哈希和运行清单追溯。

若正式实验完整但主要排序未复现且原因仍只是推测，则“实验执行完成”，但S7不通过，也不得创建 `paper-static-baseline-v1.0` 标签。

## 5. 重跑判定规则

- 仅复制、拆分或移动文件且算法文件哈希与调用行为不变：不重跑1600次，只执行静态测试、固定种子等价检查和小规模独立运行。
- 改变输入、编码、初始化、epsilon、解码、Makespan、TEC、停止预算或算法调用顺序：所有受影响算法的旧统计结果失效。
- QNSGA-II运行时间发生变化且三个比较算法以其时间为预算：QNSGA-II和三个比较算法均需重新运行。
- 统一目标影响A/B/C/full：四个消融均需重新运行。
- 只有在S1–S6通过且小规模预验收成功后，才允许启动正式重复实验。

## 6. 验收结论格式

最终报告必须分别回答：

1. 工作是否按协议完成；
2. S0–S7每门通过、不通过或证据不足；
3. 哪些旧证据被继承，哪些实验被重跑及原因；
4. 论文主要静态结论是否获得支持；
5. 是否允许创建 `paper-static-baseline-v1.0` 标签；
6. baseline可用于什么、不能用于什么。
