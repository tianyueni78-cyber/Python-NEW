# 达到论文静态 baseline 验收标准的工作流

## 1. 起点：直接继承的现有成果

以下内容从 `Python-NEW` 冻结提交继承，不从头重写：

- 静态数据层、Brandimarte Mk01–Mk10及资源文件；
- 染色体、初始化、静态解码和共享多目标算子；
- QNSGA-II、N1–N6和Q-learning；
- NSGA-II、MOEA/D、MOPSO独立入口；
- A、B、C、full消融；
- HV、IGD、C-metric、Spacing及批量实验系统；
- Gate 1–6、比较算法、消融、指标和静态协议测试；
- 论文—MATLAB—Python映射、差异台账和现有1600次静态结果。

现有1600次结果作为 `matlab_observed` 历史证据保留。它们是否可直接用于论文静态baseline，由后续差异裁决和重跑规则决定。

## 2. 阶段P0：建立独立静态候选分支

工作：

1. 从提交 `dca5adda2bfb9ca9252caabaff05f31b637772b8` 建立独立worktree和候选分支；
2. 保留全部静态权威代码、测试、规格和证据；
3. 排除动态入口、动态配置、动态测试和动态结果；
4. 生成文件来源、分类和SHA-256清单；
5. 检查静态入口的导入闭包。

检查点：S0。

停止条件：来源不一致、用户未提交改动可能被覆盖，或静态代码无法与动态模块机械分离。

本阶段不运行1600次实验。

## 3. 阶段P1：复用审计与四项差异裁决

重新裁决四项尚未关闭、会影响论文静态身份的核心冲突，不重复已有全部源码考古：

1. 三段编码与MATLAB静态五段编码；
2. 论文60/20/20与MATLAB静态40/30/30初始化；
3. 论文epsilon与MATLAB静态epsilon；
4. Makespan返卸载站和TEC能耗组成。

同时复核三项已有记录但会影响比较身份和公平性的协议：

1. MOEA/D随机评价削减是否属于论文比较算法；
2. MOPSO附加VNS是否属于论文比较算法；
3. 固定代数与相同CPU时间分别用于哪个实验，是否与论文协议一致。

每项按同一模板记录：

- 论文位置和原文含义；
- MATLAB实际入口、函数和活动语句；
- 输入、参数文件或保存结果证据；
- 两种选择对染色体、解码、奖励、预算和旧结果的影响；
- 正式 `paper_static` 选择；
- `matlab_observed` 保留方式；
- 是否触发重验或重跑。

优先使用工作区现有MATLAB原代码。只有缺少作者正式入口、工作区、参数文件或原始结果且该缺口会改变裁决时，才向用户索取具体材料。

检查点：S1–S5中的定义和算法身份部分。

停止条件：任一项存在可能改变baseline身份的未解决冲突。

## 4. 阶段P2：形成独立paper_static配置

工作：

1. 保留现有 `matlab_observed` 模式；
2. 以最小变更新增 `paper_static` 模式；
3. 所有静态算法统一调用P1确认的数据、染色体、解码和目标；
4. 将初始化、epsilon、预算和停止规则写入显式配置；
5. 禁止用算法名称隐式切换Makespan或TEC；
6. 每次独立运行重新创建Q表、随机数生成器和算法状态；
7. 对每项行为变化添加对应固定输入测试和差异记录。

检查点：S1–S5。

停止条件：为了统一口径需要重写无关算法，或关闭 `paper_static` 后不能恢复冻结行为。

## 5. 阶段P3：确定性和小规模预验收

按成本从低到高执行：

1. 固定资源文件和固定染色体，比较MATLAB与Python输入；
2. 比较解码时间表、AGV移动、充电、Makespan和TEC；
3. 固定目标矩阵，比较排序、拥挤度、选择和指标；
4. 固定随机流，检查初始化、epsilon、动作、奖励和Q更新；
5. 每个优化器和消融运行最小代数smoke test；
6. 选1个小实例执行少量固定种子的完整协议；
7. 同时执行论文预算和等真实解码预算的小规模对照，确认两者记录不会混用；
8. 再对Mk01–Mk10各执行1次协议预跑，估算正式运行时间和失败风险。

检查点：S1–S6。

停止条件：目标身份不统一、固定结果不一致、消融改变了额外因素、预算计数不完整，或预跑不能稳定复现。

本阶段结束后生成“旧结果复用与重跑影响表”。在此之前不决定是否重跑全部1600次。

## 6. 阶段P4：冻结正式静态协议

在没有正式新结果的情况下固定：

- 实例和数据版本；
- 四个优化器与四个消融；
- 参数、种群和停止规则；
- 20次独立重复及种子政策；
- QNSGA-II到比较算法的预算传递；
- 论文复现协议与等真实解码次数机制协议，两者的主张和结果分开；
- 实际解码次数、墙钟时间、硬件、线程/进程和计时口径；
- 失败、超时、中断和恢复规则；
- 主要和次要指标、统计单位、配对关系、效果大小、区间估计、检验假设、非参数备选和多重比较处理；
- 参考前沿构建规则及其不得用于调参、奖励或固定配置选择的边界；
- 20次重复的论文来源及其精度/功效限制；
- 原始结果目录、命名、清单和哈希。

检查点：S6。

停止条件：协议仍含未裁决参数，或根据预跑结果事后选择有利指标、种子或算法配置。

## 7. 阶段P5：按影响范围执行正式实验

重跑范围由P3影响表决定：

- 若仅完成静态剥离且行为与冻结版本等价，复用现有1600次结果，不进行全量重跑；
- 若只有部分算法行为或目标变化，只重跑受影响算法及其预算依赖算法；
- 若统一目标同时影响QNSGA-II、三个比较算法和四个消融，执行完整1600次新实验。

运行顺序：

1. 按实例和重复编号运行QNSGA-II；
2. 将同实例同重复的已确认预算传给NSGA-II、MOEA/D和MOPSO；
3. 运行A、B、C、full公平消融；
4. 每次运行立即写入配置、结果和manifest；
5. 中断后从manifest恢复，不覆盖成功结果；
6. 完成后核查运行数量、唯一键、种子、失败记录和文件哈希。

检查点：S6执行证据和R1数据完整性。

## 8. 阶段P6：指标、推导与最终验收

交付顺序固定为：

1. 原始结果：全部实例、种子、算法、目标、Pareto解、评价次数、耗时和失败；
2. 指标结果：HV、IGD、C-metric、Spacing、描述统计、效果大小和不确定性；
3. 推导链：原始事实 → 指标观察 → 排除的替代解释 → 支持或反对的论文主张；
4. 结论：复现、未复现、证据不足及适用边界；
5. S0–S6逐门判定，决定是否创建 `paper-static-baseline-v1.0` 标签；
6. R1单独判定，决定是否创建 `paper-static-reproduction-v1.0` 标签。

S0–S6全部通过后冻结 `paper-static-baseline-v1.0`。R1通过后才冻结 `paper-static-reproduction-v1.0`。若实验完整但R1未通过，保留baseline、全部原始结果和差异调查，不降低标准、筛选结果或反向修改实现。

## 9. 最短执行路径

```text
继承冻结Python-NEW
→ 建立静态候选分支
→ 裁决4个关键冲突
→ 新增paper_static统一配置
→ 固定输入与小规模预验收
→ 冻结正式协议
→ 按影响范围复用或重跑
→ 原始结果—指标—推导—结论
→ S0–S6冻结baseline
→ R1独立判断论文统计结论
```
