# Python Baseline 复现总计划

## 1. 总目标

以论文及其真实 MATLAB 源代码为依据，在 Python 中完整重建论文实验体系，使其能够作为后续算法创新的可信、公平、可重复 baseline。

最终版本必须覆盖：

- DFJSP-T 问题模型、论文数据及约束；
- QNSGA-II 完整主算法；
- NSGA-II、MOEA/D、MOPSO 三种对比算法；
- 论文中的消融版本；
- 订单取消、机器故障、AGV 故障三类动态事件及对应重调度策略；
- 论文使用的目标函数、评价指标和实验协议；
- MATLAB–Python 一致性测试、随机种子、原始结果和差异台账。

本计划服从仓库根目录的 `AGENTS.md`。缺少任意一个验收 Gate，均不得宣称完整 baseline 成立。

## 2. Baseline 的组成

本项目中的 baseline 不是单独一篇参考论文，也不只是一个算法文件，而是三类参照对象及其共同实验基础：

1. **完整 QNSGA-II**：后续创新算法最直接的比较对象；
2. **NSGA-II、MOEA/D、MOPSO**：用于判断改进相对通用多目标算法是否有效；
3. **消融版本**：用于识别混合初始化、邻域搜索、Q-learning 等模块分别解决的问题。

三类算法必须共享真正相同的问题数据、解码规则、目标函数和评价协议，但不得错误共享各算法特有的搜索机制。

## 3. 行动计划

各阶段新增的审计、规格、测试证据和报告，统一存放在 `reproduction/01_确认源码范围` 至 `reproduction/15_冻结baseline` 对应目录中。跨阶段总计划保留在本文件。

| 阶段 | 要执行的动作 | 必须覆盖的内容 | 阶段产物 | 通过条件 |
|---|---|---|---|---|
| 1. 确认源码范围 | 清点 MATLAB 文件夹，识别真实实验入口、正式版本、备份和废弃版本 | 主算法、对比算法、消融实验、三类动态实验、数据及指标 | MATLAB 源码清单、实际调用路径 | 每项论文实验都对应到实际入口；不得仅凭文件夹名称判断 |
| 2. 提取完整算法规格 | 对照论文和 MATLAB 调用链，记录模型、公式、参数和执行顺序 | DFJSP-T 约束、染色体、初始化、解码、目标函数、遗传算子、邻域、Q-learning、动态策略 | `算法规格.yaml`、论文—源码映射表 | 所有关键规则都有论文位置、源码位置和运行证据 |
| 3. 锁定实验协议 | 固定数据、种群规模、迭代次数、停止条件、随机种子、重复次数和指标 | 静态实验、消融实验、算法对比、动态重调度 | 实验配置及参数来源表 | MATLAB 和 Python 使用同一协议；差异不得静默修改 |
| 4. 实现统一数据层 | 将 MATLAB 实例读取方式和内部数据结构转换为 Python | 工件、工序、候选机器、加工时间、AGV、距离、速度、能耗参数 | Python 数据模型、MATLAB 数据转换器 | **Gate 1：输入一致** |
| 5. 实现染色体与初始化 | 复现论文实际使用的编码、初始化和合法性检查 | 工序序列、机器分配、AGV 分配、速度等编码段 | 编码器、初始化器、合法性测试 | **Gate 2：染色体合法** |
| 6. 实现解码与目标函数 | 按 MATLAB 调度逻辑还原完整时间推进过程 | 工序前后关系、机器占用、AGV 运输、充电、等待、Makespan、总能耗 | 解码器、目标函数、详细调度记录 | **Gate 3：固定染色体下解码一致** |
| 7. 实现共享多目标框架 | 实现各算法真正共用的基础操作 | 非支配排序、拥挤距离、Pareto 档案、选择、交叉、变异、评价预算 | 公共多目标模块 | **Gate 4：多目标算子一致** |
| 8. 实现完整 QNSGA-II | 按真实调用顺序复现论文主算法 | 混合初始化、NSGA-II 循环、N1–N6 邻域、状态、动作、奖励、Q 表更新 | Python QNSGA-II 完整入口 | **Gate 5：Q-learning 和主算法行为正确** |
| 9. 实现三种对比算法 | 在相同数据、解码器、目标函数和实验预算下分别实现 | NSGA-II、MOEA/D、MOPSO 各自的优化循环 | 三个独立算法入口 | 不把 QNSGA-II 特有机制错误共享给对比算法；比较预算一致 |
| 10. 实现消融版本 | 通过明确开关移除指定创新模块 | 基础 NSGA-II、混合初始化版、随机邻域版、完整 QNSGA-II | 消融配置及入口 | 每个版本只改变被消融模块，其余条件保持一致 |
| 11. 实现动态重调度 | 复现事件产生、状态更新和重调度策略 | 订单取消、机器故障、AGV 故障及论文使用的重调度策略 | 动态事件模块和实验入口 | **Gate 6：事件确实发生，重调度状态正确** |
| 12. 实现指标与实验系统 | 自动运行论文规模实验并完整留痕 | Pareto 解、论文指标、RSI、运行时间、种子、原始结果、图表数据 | 批量实验程序、每次运行清单 | 任意结果都能追溯到代码版本、配置、输入和种子 |
| 13. MATLAB–Python 逐层对照 | 使用相同输入比较数据、染色体、中间状态、目标值和算子输出 | 七个 Gate 对应的固定测试样本 | 一致性测试及差异台账 | 确定性模块满足误差要求；随机模块满足行为和统计一致性 |
| 14. 论文级重复实验 | 按锁定协议运行完整 QNSGA-II、对比算法、消融和动态实验 | 多实例、多算法、多随机种子、独立重复实验 | 原始结果、汇总表、统计分析 | **Gate 7：统计复现完成** |
| 15. 冻结 baseline | 审查所有差异并形成可引用版本 | 已解释差异、未解决问题、适用范围、运行方法 | `baseline-v1.0`、复现报告、Git 标签 | 七个 Gate 全部通过，且不存在足以推翻论文核心比较结论的未解释差异 |

## 4. 七个强制验收 Gate

- **Gate 1：输入一致**——MATLAB 与 Python 读取到相同的实例、参数、维度和语义。
- **Gate 2：染色体合法**——编码、初始化、修复及其约束与基准实现一致。
- **Gate 3：解码一致**——固定染色体下的调度过程、目标值和关键中间状态一致。
- **Gate 4：多目标算子一致**——排序、拥挤距离、选择及环境选择行为一致。
- **Gate 5：Q-learning 行为正确**——状态、动作、奖励、Q 表更新和邻域选择符合基准实现。
- **Gate 6：动态事件有效**——事件真实改变系统状态，重调度输入和输出合法且可核查。
- **Gate 7：统计复现完成**——按照论文实验协议完成独立重复实验并保存全部原始证据。

## 5. 每个模块的执行闭环

每个模块均按以下动作完成，不采用“全部写完后再统一检查”的方式：

1. 找到论文定义；
2. 找到 MATLAB 的实际调用路径；
3. 分别记录“论文描述”“MATLAB 实现”“推断或未确认项”；
4. 制作固定输入和 MATLAB 参考输出；
5. 先建立 Python 一致性测试；
6. 实现满足基准行为的最小 Python 模块；
7. 对比最终输出和关键中间状态；
8. 通过对应 Gate 后进入下一阶段；
9. 保存证据并提交独立 Git commit。

固定输入测试用于校准 Python 翻译是否正确，不替代论文规模的完整实验。最终仍须执行第 14 阶段规定的全部重复实验。

## 6. Baseline 边界

以下边界在整个项目中持续有效：

- 原始 MATLAB 源码保持只读；
- 不擅自更换数据、约束、目标函数、能耗模型、参数或实验预算；
- 不为追求 Python 代码风格而改变 MATLAB 的基准行为；
- 论文与 MATLAB 不一致时登记差异、提供证据，不静默选择；
- 疑似错误的修复版本必须与忠实复现版本分离；
- 公共底层只共享经过确认确实相同的逻辑；
- 对比算法不得继承 QNSGA-II 特有机制；
- 消融版本除指定模块外不得改变其他实验条件；
- 确定性模块要求逐项一致；随机算法要求实验协议一致并进行统计验证；
- baseline 冻结后，创新算法在独立模块或分支上开发，不反向修改 baseline 以美化结果；
- 任一 Gate 未通过时，必须标记当前状态和阻塞原因，不得宣称完整 baseline 成立。

## 7. 最终交付物

完整 Python baseline 应至少包含：

```text
Python baseline
├── DFJSP-T 问题模型和论文数据
├── 编码器、初始化器、解码器
├── Makespan 和能耗目标函数
├── QNSGA-II 完整主算法
├── NSGA-II、MOEA/D、MOPSO
├── QNSGA-II 消融版本
├── 订单取消、机器故障、AGV 故障
├── 动态重调度策略
├── 论文评价指标
├── MATLAB–Python 一致性测试
├── 批量重复实验入口
├── 随机种子、配置和原始结果
└── 差异台账与 baseline 复现报告
```

只有在上述交付物齐全、七个 Gate 全部通过并完成差异审计后，才冻结和发布 `baseline-v1.0`。
